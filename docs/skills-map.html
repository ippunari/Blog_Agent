blog-collect — 수집

/blog-collect [am|pm] [--hours N]

영어·한국어·일본어·중국어권 AI·보안 소식과 일본 독자의 질문을 모아, 같은 사건을 묶은 후보 목록(최대 약 40건)을 만든다. 축별·언어별 건수 없이 우리 회사에 중요한 순서 하나로 고른다 — ① 미국 주요 AI 기업의 새 발표·신기술 + 급한 보안(실제 악용 중·일본 중소기업 경로의 사고) ② 바로 글이 되는 재료(사용법·도입·개발 발주) ③ 그 밖의 AI 새 소식 — 급하지 않은 보안은 남기지 않음 (PHP·보안은 입구일 뿐, D84). 40건은 상한일 뿐. 매일 2회.

입력

  • sources.json 출처 목록 (피드·검색 — 정부 도입 출처 経産省·中小企業庁·総務省·IT導入補助金·IPA DX, 반응 출처 はてブ·Qiita·Zenn 포함)
  • tracked_products.json 추적 제품 (ChatGPT·Claude·Gemini·Workspace·M365 Copilot·NotebookLM 공식 업데이트, D82)
  • seed_keywords.json 자동완성 씨앗 키워드
  • 직전 candidates/ 파일 (수집 범위 = 그 시각 −24시간, 이미 수집한 글 표시)
  • 웹: RSS·CISA KEV·Google 뉴스 RSS(한국·중국 회사 발표, D83)·Google 트렌드 급상승·Google 자동완성, WebSearch, 知恵袋·note

출력

  • candidates/YYYY-MM-DD-am|pm.md — 후보(C01…, AI → 개발 → 보안 순, 「반응」 칸)·언어별 건수·질문 입구·검색 트렌드
  • 공유 드라이브 03_Blog/candidates에 보기용 Google 문서 (머리에 doc: ID)
카드 상태
— (카드를 만들지 않음)
◆ 사람
없음 (Drive 문서는 읽고 댓글만)
스크립트
  • fetch_feeds.py 피드·KEV·트렌드·자동완성·추적 제품을 한 번에 가져옴 → $SP/fetch.json, fetch.titles.txt (출처 상태 ok·empty·error, 반응 수 はてブ·HN)
  • check_candidates.py 필수 항목·값·수집 데이터에 없는 URL·counts·검색 안 한 출처(search_done.txt)·언어별 줄 점검 (건수 상한·하한은 보지 않음, D84) + B·C 출처인데 1차 출처가 있으면 발표 일시가 1차 출처 날짜인지 (D94)
  • export_doc.py Drive용 보기 사본 md 만들기
규칙
rules/blog-collect.md (출처 표·등급 A~D·중복 처리)

고칠 때

  • 출처 추가·삭제 → rules/blog-collect.md 표와 sources.json을 함께 / 추적 제품 → tracked_products.json + rules 「추적 제품」 줄
  • 고르는 순서(중요도)·보안 기준 → SKILL.md 5장 5번 + rules/blog-collect.md 「수집 범위와 상한」 (D84)
  • 후보 상한·뺄 것 → SKILL.md 5장 + rules/blog-collect.md / 후보 파일 형식 → SKILL.md 6장 (blog-topic이 이 형식을 읽으므로 같이 확인)

blog-topic — 주제 선정

/blog-topic · select T01 … · 중단 <slug> · 직접 "주제" URL

후보에 일본어 검색어를 찾고 점수를 매겨 순위표를 내고, 추천 ○를 넣은 시트를 기록용으로 올리고(아침 3 · 저녁 3 — 속보 2(급한 보안이 있으면 그중 1, D86)·깊이 새 글 1, D72), 확인을 기다리지 않고 ○ 주제의 카드를 바로 만든다 (D67).

입력

  • 새 candidates/ 파일 + 앞 topics/ 파일 (이월 후보 — 속보는 바로 앞 1개, 깊이는 최근 5 업무일 deadline.py --carry, D92)
  • briefs/*.md (이미 확정된 주제는 뺌)
  • experience.json 회사 경험 점수 (D39 — 값은 D71: AI 활용·도입·개발 중심)
  • topics/existing_posts.json 기존 글 목록 (1키워드 1글)
  • Google 자동완성·WebSearch 상위 결과
  • B 모드: A에 이어서 순위표의 ○ 행 (자동) / select T..로 사람이 더한 후보 / 대화로 받은 대표 한마디

출력

  • A: topics/YYYY-MM-DD-am|pm.md 순위표·후보 상세(T01…)
  • A: 03_Blog/topics 시트 (지난 시트는 지난 시트 폴더로)
  • B·C: briefs/<slug>.md 주제 카드
카드 상태
(새 카드) → 조사 대기 또는 기존 글 업데이트
◆ 사람
없음 (D67). 바꾸고 싶을 때만 대화로 select T..·「중단 <slug>」·대표 한마디
모드
A 순위 매기기 → B 카드 만들기(○ 자동) / C 직접 주제(확인 없음) (시트·candidates·topics에 아무것도 안 씀)
스크립트
  • list_posts.py 사이트맵에서 기존 글 제목·메타 → existing_posts.json·.titles.txt·.stale.txt
  • suggest.py 키워드 자동완성 (축별 질문형 꼬리말, D43)
  • check_topics.py 점수 1~5·총점 재계산·순위표 구성·URL 점검 + 키워드(D80: 상위 구성 검색어·속보 사건어·이길 여지 문턱 / D87: 메인이 근거에 그대로·서브 일본어 질문형·사건어 경고·수요 상한) + 속보 ○ 2개·보안은 「급한 보안」만(D86) + 속보는 사람 실습 없음(D79)
  • export_sheet.py 순위표 → 시트용 xlsx
  • deadline.py 속보 마감 = 공표 + 72시간, 업무 시간(평일 9~18시) 밖이면 다음 업무일 12:00 · 남은 업무 시간 (D88 — blog-research도 씀). 시각 없는 날짜는 받지 않는다 — 확인된 가장 늦은 시각으로 (D94)
규칙
rules/blog-topic.md (주제 축·점수표·속보/일반 판정·회차 운영·시트 칸), rules/blog-perspective.md (대표 한마디)

고칠 때

  • 시트 칸 → rules/blog-topic.md 「시트」 + export_sheet.py / 카드 형식 → SKILL.md 9장 (뒤 스킬이 모두 읽음)

blog-research — 조사

/blog-research [slug] · 실습 끝났어 <slug>

1차 출처까지 찾아가 원문을 저장하고, 사실마다 원문 문장·등급·확인일을 붙인 조사 노트를 만든다. 상위 글 분량은 모든 글(속보는 상한 참고용, D58·D69), 일반 글은 경쟁 글·차별 포인트, AI 실습 글은 직접 써 본 결과까지. 사건어가 메인에 없는 속보는 사건어로도 검색해 일본어 해설 유무를 적는다 (D93). 1차 출처의 화면·도해는 「이미지 후보」로 모으기만 한다 — 글에 넣는 것은 권리 승인 뒤 (D103).

입력

  • briefs/<slug>.md (조사 대기·기존 글 업데이트)
  • 카드의 candidate: 후보 항목
  • 웹 페이지 (fetch_page.py로 저장한 것만 근거)
  • 개편 글: 대상 기존 글
  • 「실습 끝났어」: Drive 실습 문서에 팀원이 적은 결과

출력

  • research/<slug>.md — 요약·핵심 사실표(S1…)·수치표·경쟁 글·차별 포인트·상위 글 분량·직접 써 본 결과
  • 카드: research: 줄, 속보는 확인한 1차 출처 공표 시각으로 deadline (blog-topic/deadline.py, 업무 시간 기준 D88 · 날짜만이면 확인된 가장 늦은 시각 D94)
  • 사람 실습: 03_Blog/trials 실습 문서, 카드 trial_doc·trial_due (기한 = +1주 17:00)
카드 상태
조사 대기 → 설계 대기
◆ 사람
trial: 사람 카드만 — 기다리지 않는다: 자리 표시로 Ghost 초안([실습 필요])까지 간 뒤, 팀원이 실습 문서대로 해 보고 결과 기입 → 「실습 끝났어 <slug>」 → 노트 → 설계 행 → 초안 섹션 → 재대조 → 같은 초안 갱신 (D79). 속보는 사람 실습 없음. converted_from: 속보 카드는 노트에 일반 범위만 보충
스크립트
  • fetch_page.py 페이지를 본문 텍스트 + 링크 목록으로 저장 (원문 문장의 증거, 다른 스킬도 씀). PDF는 pdftotext, 없으면 pypdf (pip3 install pypdf)
  • body_chars.py 경쟁 글 본문 글자 수·중앙값 (D47)
  • check_research.py 원문 문장이 저장한 페이지에 실제로 있는지·등급·날짜·URL 점검
  • export_trial.py 사람 실습 문서 md 만들기 / drive_folders.json trials 폴더 ID
규칙
rules/blog-research.md (근거 기준·1차 출처 순서·범위·실습·노트 형식)

blog-distribute — SNS 배포

/blog-distribute [slug] · 올려 · 올려 <slug> · 올려 오늘|YYYY-MM-DD

발행 직후 바로(「발행했어」에 이어서) 최종 글을 5개 SNS에 맞게 플랫폼마다 새로 쓰고 — 읽는 사람·切り口(X 数字 / Threads 試した·気づき / Facebook 場面 / LinkedIn 判断 / note 要約)·틀이 다르다 (D75) — 날짜별 시트를 공유 드라이브에 올린다. 사람이 확인하고 「올려」 하면 Windsor.ai MCP로 Threads·Facebook 페이지·LinkedIn 회사 페이지에 게시한다. 「올려」가 승인 — 없이는 보내지 않는다 (철칙 2, D66·D74).

입력

  • briefs/done/YYYY-MM/<slug>.md (발행 완료, url·rep_comment)
  • drafts/done/YYYY-MM/<slug>.md 최종 글 — SNS 사실은 여기 있는 것만 (LinkedIn 링크 카드 제목·설명은 og_title·excerpt)
  • outlines/done/YYYY-MM/<slug>.md 「SNS 포인트」(수치·의견·질문)
  • 대표 이미지 <slug>_hero.webp (X·note에 사람이 첨부)
  • Windsor.ai 연결 계정 (사람이 연결, ID는 실행 때 get_connectors) · accounts.json 플랫폼별 test|company

출력

  • publish/done/YYYY-MM/<slug>/sns.md 플랫폼별 切り口·本文·返信(X)/リンク(LinkedIn·Facebook) (UTM 링크) — 원본
  • sns_posted.json 게시 기록 (플랫폼별 id·주소·시각·계정, 실패는 error)
  • 카드: sns:·sns_posted_at·sns_platforms
  • sns/YYYY-MM-DD.md 날짜별 모음 — ✅ 올림 / ⏳ 「올려」 대기 / ✋ 붙여 넣기 / ❌ 실패 (보기용, 스크립트가 다시 만듦, 머리에 시트 ID)
  • 공유 드라이브 03_Blog/sns 「BlogAgent SNS 문안 YYYY-MM-DD 아침|저녁」 회차 시트 — 한 행 = 글 × 플랫폼, 필터, 대표 이미지 주소, 사람이 적는 「게시 주소」 칸 (D76)
카드 상태
발행 완료 그대로 (done 폴더 안에서 sns 줄만 추가)
◆ 사람
  1. 회차 시트 확인 → 「고쳐」 / 「올려 아침」(그 회차 전부) / 「올려 <slug>」 / 「올려 오늘」(목록 → 「응」)
  2. ✋ 행: X(본문 + 링크 답글)·note(모든 글 — 제목·본문·見出し画像) 붙여 넣기, 시트의 대표 이미지 주소로 첨부 → 「게시 주소」 칸에 적고 「다 올렸어 아침」
