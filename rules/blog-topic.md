# blog-topic (주제 선정)

> v1.7 2026-11-20 · 운영하며 보강 · 공통 규칙: [common.md](common.md)

## 목적
후보마다 검색어를 찾고 점수를 매겨, 회차마다 쓸 글을 추천하고 사람이 확인하게 한다. 평일 하루 6편 = 속보 4(아침 2 + 저녁 2) + 깊이 있는 글 2(새 글 1 + 기존 글 개편 1)

## 입력
- blog-collect의 후보 목록
- blog-measure의 점수 기준 조정 결과 (승인된 것만)

## 출력
- Google Sheets에 상위 후보 (회사 공유 드라이브 「Atatakai Digital」 › `03_Blog/topics`에 새 시트로 올림) + `topics/YYYY-MM-DD-am|pm.md` 상세 기록
- 선택된 주제마다 `briefs/<slug>.md` 주제 카드
- 선택된 주제: 글 종류, 메인 키워드 1 + 질문형 서브 키워드 3~5, 가제목 → blog-research로 (대표 한마디가 있으면 함께)

## 사람 확인 지점
- ◆ 에이전트가 추천에 ○를 미리 넣은 시트를 사람이 확인한다. 바꿀 때만 같은 구분 안에서 ○를 옮기고 「확인했어」 (대표·팀원). **확인 없이는 진행하지 않는다** (D32)

## 규칙

### 주제 축
- **AI**: 중소기업 업무에 쓰는 AI / 일본 중소기업에 영향이 있는 해외 AI 뉴스 / 업무와 이어지는 도구 사용법
- **보안**: 중소기업 홈페이지·메일·PHP·WordPress / 일본 기업 보안 사고 해설(교훈 중심)
- **개발**: 발주·견적·MVP·IT 담당자가 없는 회사

### 쓰지 않을 주제
- 루머·미확인 정보만 제외
- 엔터·창작 AI, 투자·실적 뉴스, 개발자 심층 기술은 허용 — 점수가 낮아 자연히 후순위. 쓸 때는 "중소기업에 무슨 의미인가"로 풀어 쓴다

### 후보 만들기
- candidates의 후보(C번호)에 더해, **질문 입구의 질문·검색어를 같은 뜻끼리 묶어 일반 글 후보**를 만든다 (뉴스가 없는 축, 특히 개발을 채운다)
- 점수는 2단계: ① 검색 없이 1차 점수 → 속보 AI 몫 상위 5개, 속보 보안·개발 몫 상위 8개, 깊이(일반) 상위 8개 ② 이것만 검색어·일본어 상위 결과를 조사해 최종 점수
  - 1차 점수의 자료부족 임시값은 「일본어 보도 없음 4 / 있음 2」. 단 **일본 회사·기관의 보안 사고는 보도가 있어도 4** — 사고 보도는 많아도 중소기업용 교훈 해설은 드물다. 최종 점수는 검색으로 정한다 (D33)
- 순위표 파일(`topics/`)에는 표마다 상위 5개. 시트에는 추천 + 구분마다 다른 후보 최대 3개
- 후보마다 「실습」: 에이전트 가능 / 사람 필요 / 해당 없음 (AI 실습 글을 고를 때 쓴다)

### 검색어 찾기
- 후보마다 독자가 실제 검색하는 일본어 메인 키워드 1개
- 질문형 서브 키워드 3~5개 (자동완성·「他の人はこちらも質問」·知恵袋). 질문형 = 질문 의도가 있는 검색어(〜とは·確認方法·対策·違い·費用 등)도 포함
- 실제로 확인한 검색어만 쓴다. 근거가 약하면 「추정」 표시

### 점수표 (전환 연결성 최우선)
| 기준 | 비중 | 1~5점 판단 |
|---|---|---|
| 전환 연결성 | 35% | AI 도입 가이드·보안 대책·개발 발주 = 5 / 보안 사고 해설 = 4 / 업무 활용 = 3 / 사용법 = 2 / 속보 = 1 |
| 일본어 자료 부족 | 20% | 일본어 검색 상위에 쓸 만한 글이 없으면 5 |
| 검색 수요 | 20% | 자동완성·Q&A에 반복 등장하면 높게. 속보는 관심이 오르는 중인지로 |
| 회사 경험 | 15% | **회사 서비스와 이어지는가**: PHP Free·迅速開発·AI 도입 지원에 바로 이어지면 5 / 간접 3 / 무관 1 (분야별 값: `.claude/skills/blog-topic/experience.json`, D39) |
| 수명 | 10% | 1년 이상 유효 5 / 1주 안에 묻히면 1 |

### 속보 / 일반 판정
- **속보**: 발표 72시간 이내 + 관심 상승 중
- **일반 글**: 질문형 검색어가 있고 6개월 이상 유효
- 속보와 깊이(일반)는 **따로 순위**를 매긴다
- **회차마다 속보 = AI 1 + 보안·개발 1**: 속보는 「AI」(주제 축 AI)와 「보안·개발」로 순위를 나누고 각 1편을 추천한다. 한쪽 후보가 없으면 다른 쪽에서 2편 (D28)
- 속보는 두 종류 (D32)
  - **해외 화제**(주로 AI): 일본어 자료가 아직 없는 것이 가치. 발표 24시간이 지났고 일본어 보도가 이미 있으면 속보에서 뺀다 → 교훈이 있으면 깊이 후보로
  - **대응이 필요한 보안 소식**(취약점·사고): 일본어 보도가 있어도 72시간 안이면 후보. 24시간 이내 우선
- 「발표」는 **원래 공표일**이다. 주간 보고·취약점 목록에 다시 실린 날이 아니다 (JPCERT Weekly Report, CISA KEV 등)
- 총점 = 가중합 ÷ 5 (100점 만점). 동점이면 자료부족 → 일본어 보도 없음 → 최근 발표 순

### 회차 운영 (D32)
| 회차 | 추천(○) | 보는 후보 |
|---|---|---|
| 아침 | 속보 AI 1 · 속보 보안·개발 1 · 깊이 새 글 1 · 깊이 개편 1 (4개) | 아침 수집분 + 전날 저녁에서 넘어온 속보 + 1주 안의 남은 깊이 후보 |
| 저녁 | 속보 AI 1 · 속보 보안·개발 1 (2개) | 저녁 수집분 + 그날 아침에서 넘어온 속보 |
- **이월**: 속보는 바로 앞 회차 한 번만 넘어온다(마감 전인 것만). 깊이는 1주. 확정된 주제는 다시 나오지 않는다(`briefs/` 대조)
- **추천**은 구분마다 총점 1위. 건너뛰는 경우(메모에 이유): 이미 고른 주제·키워드 겹침 / 마감까지 6시간 미만 / 공표일 미확인·미확인 주장 / 공식 발표 없는 실명 사고
- **깊이 새 글 (주 5편) = AI 실습 2 + 보안·개발 3** (D35)
  - **화·목 아침은 AI 실습 몫**: 「깊이 새 글」 표에 AI 실습 후보(주제 축 AI · 경로 일반 · 실습이 「에이전트 가능」 또는 「사람 필요」)만 따로 순위를 매긴다 — 전환 점수 차이로 보안·개발 글에 밀리지 않게
  - AI 실습 후보가 없는 날은 보안·개발 글로 채우고, 그 주 다른 날 아침에 AI 실습을 넣는다 (주 2편 유지)
  - 월·수·금 아침은 보안·개발 글 중심 (총점 순)
- **깊이 개편**: 「[更新]」 제안 우선, 없으면 사실이 낡은 기존 글
- **최종 결정은 사람이 확인한 ○**. ○는 구분마다 1개 — 다르면 한 번 확인하고, 사람이 그렇게 정했으면 따른다
- **확정한 속보가 발행 전에 마감을 넘기면** 속보로 발행하지 않고 **교훈 글(깊이 있는 글)로 돌린다**. 주제 카드의 route를 「일반」으로 바꾸고, 사람에게 바뀐 것을 알린다 (D34)

### 1키워드 1글
- 메인 키워드가 기존 글과 겹치면 새 글 대신 기존 글 업데이트를 제안한다

### 시트 (Google Sheets)
- 회차마다 새 시트 1장을 회사 공유 드라이브 `03_Blog/topics`에 올린다. 이 폴더에는 **지금 확인할 시트 1장만** 두고, 지난 시트는 `03_Blog/topics/지난 시트`로 옮긴다 (rules/common.md 7장 D: 회사 계정끼리만 공유)
- 모양: 맨 위 안내 1줄 → 「추천」 줄(○ 미리 들어 있음) → 「다른 후보」 줄(구분마다 최대 3개, 넘어온 후보는 「이월」 표시). 아침 최대 16줄, 저녁 최대 8줄
- 구분: 속보 AI / 속보 보안·개발 / 깊이 새 글 / 깊이 개편
- 사람은 「선택」 칸 드롭다운으로 ○를 옮기고 「선택자」에 이름을 적는다. 가제목은 시트에서 고쳐도 된다
- 칸 순서: 구분 / 선택 / 대표 한마디(선택 칸 — 쓰고 싶을 때만, 기다리지 않음) / 추천 이유 / 가제목 / 마감 / 실습 / 글 종류 / 메인 키워드 / 총점 / 이월 / ID / 1키워드1글 / 서브 키워드 / 점수 5개 / 원문 URL / 상세 파일 / 선택자 / 메모
- `topics/` 파일은 상세 기록(모든 후보·점수 근거·검색 결과)으로 남는다

### 발행 리듬
- 평일 하루 6편: 속보 4(아침 2 + 저녁 2) + 깊이 있는 글 2(새 글 1 + 기존 글 개편 1) → 주 30편 + 뉴스레터 1회 (D31)
