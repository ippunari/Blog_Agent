# blog-publish (발행)

> v2.2 2026-11-28 · 운영하며 보강 · 공통 규칙: [common.md](common.md)

## 목적
이미지를 준비하고, 사람의 최종 확인을 받아 Ghost에 발행·예약한다.

## 입력
- 완성 원고 + 메타 정보

## 출력
- Ghost 게시글(초안 → 예약/발행), 시트의 발행 기록 → blog-distribute로
- **임시 방식** (⚠ 대표 + 기술 보안팀 확인 전, D23·D50): `publish/<slug>/` — `card1-style.html`(템플릿 CSS 카드) · `card2-body.html`(본문 카드) · `preview.html` · `ghost.md`(Ghost 입력값·미리보기 체크리스트) · `hero_prompt.md` · 대표 이미지 · 발행 뒤 `backlinks.md`. 사람이 Ghost에 붙여 넣고 발행·예약한다.
- **초안 업로드** (D62): 이 컴퓨터의 `.env`에 Ghost Admin API 키가 있으면 `ghost_upload.py`가 같은 파일을 Ghost에 **초안(draft)으로만** 올린다(같은 글은 같은 초안을 갱신, `publish/<slug>/ghost_post.json`). 발행·예약·이메일·삭제 요청은 스크립트에 없다 — 사람이 Ghost 미리보기를 보고 발행한다(철칙 2). 키가 없으면 붙여 넣기 방식 그대로 발행 기록은 시트 대신 `briefs/done/` 카드의 `published_at`·`url` (시트 연결은 13번)

## 사람 확인 지점
- ◆ 미리보기 최종 확인
- ◆ 사람 실습 카드: Ghost 초안 제목 `[실습 필요]`를 보고 실습 → 실습 문서에 결과 → 「실습 끝났어」 (D79). 표시가 있는 동안은 발행하지 않는다

## 규칙
- **초안 표시 변환** (blog-draft에서 넘어온 것): `[S번호]`는 지운다 — **본문에 각주 번호를 내지 않는다**. 출처는 문장 속 출처명(「IPAによると」「PHPの公式は」)과 글 끝 SOURCES 목록으로 (D51), `[EXP]`·`[OP]`·`[?]`·`<!-- 라벨 -->`·`<!-- 차별 N -->` 주석은 지운다(라벨은 디자인용 작은 글씨로), `:::` 상자 → **사이트 기사 템플릿의 상자** (Ghost 기본 카드가 아님, D50). 「초안 메모」·「다듬기 메모」 절은 발행하지 않는다 (D46, D47)
- **기사 템플릿** (D50): 기존 글과 같이 HTML 카드 2개 — ① 스타일 카드 = 사이트 HowtoAI 記事テンプレート CSS 그대로(`template/hikari-base.css`) + 보충분(`template/extra.css`) ② 본문 카드. 상자 대응: 3行まとめ → 요약 상자(`cs-key`) / こんな方に·わかること → 독자 상자(`cs-rc`) / 案内 → ヒカリちゃん 그림 상자(`hta-hikari`) / まとめ → 말풍선(`hta-say`, ヒカリちゃん 아바타) / 代表ヤンのひとこと → 말풍선(대표 아바타) / note → 주의 상자(`cs-lim`) / SOURCES → `cs-src` / 글 끝 CTA → `cs-cta`(보조 CTA는 아래 한 줄) + 옆 칸 버튼. 문장은 바꾸지 않는다
- **글 머리 보드** (D65): 본문 카드 맨 앞에 `hta-top`(분류 줄 `cs-crumb`·태그 알약 `cs-cat`·번호 `cs-no`·읽는 시간·更新日)을 넣는다 — 공개 글의 전체 폭 대표 이미지 + 흰 보드(목록으로·제목·요약·저자)는 사이트가 모든 글에 자동으로 그리고, hta-top은 그 보드 안의 분류 줄·태그 알약 내용이 된다(없으면 그 줄이 빠져 기존 글과 달라 보인다). 값은 `publish/<slug>/board.json`, 앞부분은 축별 고정(보안 `PHPフリー · Webセキュリティ`, AI `HowtoAI · <topic>`). ⚠ Ghost 미리보기(`/p/…`)는 사이트가 다른 간단한 화면으로 그려 보드·전체 폭 이미지가 보이지 않는다 — 최종 모양은 공개 뒤 확인
- 리드 문단은 본문 맨 앞에 그대로 둔다 (D47 뼈대). 사이트 머리에는 Excerpt가 따로 보인다
- **사람 실습 자리 표시** (D79): 초안에 `:::trial`이 있으면 본문에 「◆ 실습 필요」 상자(빨간 점선)를 넣고, Ghost **제목(title)에만** `[실습 필요] `를 붙인다 — meta_title·og_title·slug에는 붙이지 않는다(표시만 떼고 발행해도 검색·SNS 제목에 남지 않게). 이 상태로도 초안 업로드까지 하고 카드는 「실습 대기」(`ghost_draft:` 편집 화면). 「실습 끝났어」 뒤 섹션을 채워 다시 만들면 표시가 빠지고 같은 초안을 갱신, 카드 「발행 준비」. 공개 글 점검에서 `[실습 필요]`·「◆ 실습 필요」가 보이면 오류

### 이미지
- 대표 이미지 **1800×945**(1.91:1 — 사이트 기존 대표 이미지 크기, OG 공유에도 맞음, 200KB를 넘으면 같은 비율로 1600→1440→1200px), 깔끔한 일러스트 톤(매끈한 색면 — 수채 종이 질감은 파일이 무거워 쓰지 않음)
- **사이트 표시** (D64, 2026-11-21 확인): 글 머리는 데스크톱 21:9·휴대폰 16:9 박스에 **위·왼쪽 기준**으로 잘리고(`object-left-top`), 아래쪽은 본문 카드가 겹친다 → 라벨·핵심 사물·얼굴은 **아래 25%·오른쪽 끝 6% 밖**에. make_hero.py의 `hero_site_preview.png`로 가려지는 곳을 직접 본다
- **이미지만 봐도 글 내용이 보인다 — 주인공은 내용** (D64): 검색 결과·SNS 카드·글 머리에서 제목 없이 그림만 봐도 「무슨 글이고 무엇을 하라는지」 알 수 있어야 한다. ヒカリちゃん은 주인공이 아니다(없음 또는 작은 조연). 「사무실에서 노트북을 보는 사람」처럼 어느 글에나 맞는 그림은 안 된다
  - `hero_prompt.md`: ① **주제 한 줄** ② **장면 요소** 3~5개 — 글의 요점(3行まとめ·H2)과 짝지은 구체 사물·상황, 왼쪽→오른쪽으로 글의 흐름 ③ **라벨** 0~5개 — 라틴 문자 짧은 말(12자 이내, 예: `PHP`·`UPDATE`·`CHECK`), 일본어·숫자·날짜·로고 모양 금지 ④ **ヒカリちゃん** 없음/조연. make_hero_ai.py가 초안의 제목·3行まとめ·H2를 프롬프트에 붙인다
  - 화면: 글 머리 전체를 채우는 가장자리까지 꽉 찬 장면 (빈 배경·여백 없이)
  - 고를 때 **블라인드 확인**: 에이전트가 그림만 한 문장으로 설명 → 글의 주제·요점이 그 문장에 없으면 다시 만든다. 라벨 철자도 본다
- **자동 생성** (D63): 에이전트가 장면·프롬프트·alt를 `hero_prompt.md`에 쓰고 → `make_hero_ai.py`가 ChatGPT 이미지 생성(기본: Codex CLI — 사람의 ChatGPT 구독 사용량 / 크레딧이 있으면 OpenAI 이미지 API gpt-image-2.6-sunburst, ヒカリちゃん 참고 그림 포함)으로 후보 → 에이전트가 직접 보고 하나를 고른다 → `make_hero.py`. Codex 로그인도 API 크레딧도 없거나 한도에 걸렸을 때만 아래 임시 방식
- 임시 방식 (D50): 에이전트가 장면·프롬프트·alt를 `hero_prompt.md`에 쓰고 → 사람이 이미지 도구로 만들고 → `make_hero.py`가 1800×945 WebP 200KB 이하로 자르고 줄인다. **이미지를 기다리지 않는다** — 모든 글이 이미지 없이 초안을 올리고, 이미지가 생기면 같은 초안을 갱신한다 (미리보기 때 함께, D79)
- WebP 200KB 이하, 파일명은 내용을 설명하는 영어, alt는 내용 설명
- 도표는 직접 만들고 데이터 출처 표기
- AI 생성 이미지: 실존 인물·타사 로고 금지
- 스크린샷·외부 이미지는 권리 확인

### 본문 이미지 (D55)
- **에이전트가 찾아 넣고, 사람은 ◆ 미리보기에서 이미지마다 남길지 뺄지만 정한다** (기본은 남김)
- 어느 섹션에 무슨 그림을 넣을지는 **설계안 「그림 자리」**(blog-outline, D96)를 따른다. 초안에서 그 섹션·사실이 바뀌었으면 건너뛰고 이유를 ghost.md에 적는다
- 쓸 수 있는 것 (위에서부터 먼저):
  1. **편집부가 만든 그림** — 타임라인·순서도·비교·판정 그림. 노트 사실로만, 캡션에 「出典：…（図：編集部作成）」. SVG로 본문에 그대로 넣는다
  2. **미국 연방 기관 저작물** (17 U.S.C. §105, 퍼블릭 도메인 — CISA·NIST·FBI·FTC·NASA 등). 페이지에 다른 사진가·회사 크레디트가 붙은 이미지, 주 정부 자료는 제외
  3. **Wikimedia Commons** — CC0·퍼블릭 도메인·CC BY·CC BY-SA만(바꾸지 않고 그대로), 상표·초상 제한 표시가 없는 것. 작가·라이선스·원본 링크를 캡션에
- 쓰지 않는 것: 뉴스·블로그 사진, 이미지 검색 결과, 이용 조건을 모르는 이미지, NC·ND 라이선스, 타사 로고, 알아볼 수 있는 사람 얼굴, **라이선스가 깨끗해도 맥락이 부적절한 것**(사건 증거·범죄·정치·전쟁·재해·의료) / 화면 캡처·프레스킷은 ⚠ 대표 + 기술 보안팀 확인 전까지 쓰지 않는다
- 장수: 속보 2장, 일반 4장까지. 놓는 곳은 관련 섹션의 직답 바로 아래. 꾸밈용이 아니라 그 섹션 내용과 직접 관련된 것만
- 이미지마다 `publish/<slug>/images.json`에 출처·라이선스·작가·확인일을 남기고, ghost.md 「본문 이미지」 표로 사람에게 보인다
- 임시 방식: 사진은 원본 주소(Wikimedia 등)를 그대로 쓴다. Ghost API 연동 뒤에는 Ghost에 올린다

### Ghost 설정
- 필자: Ghost 스태프 계정 ヒカリちゃん 1개 (D38)
- 기본 태그 = 주제 축(AI·보안·개발), 보조 태그 = 글 종류
  - 사이트 실제 태그 slug는 `.claude/skills/blog-publish/tags.json` (D62에서 기존 글로 확인): 언어 `ja` 맨 앞 → 보안 `websekiyuritei`·`phphuri` + 질문 종류 `#cat-news|check|fix|decide|manage` / AI `howto`·`howto-ai` / 개발은 아직 없음 → 묻는다. 태그 slug를 짐작으로 정하지 않는다
  - 사이트 분류만 다른 축으로 둘 때(예: 개발 글이지만 PHPフリー 묶음): 사람이 정하면 카드 머리에 `site_axis: 보안` — 태그·글 머리 보드만 그 축을 따른다. 에이전트가 스스로 정하지 않는다 (D68)
- 공개 범위: 전체 공개
- ⚠ **글 발행 때 이메일 자동 발송은 끈다** (뉴스레터는 주 1회 따로)
- FAQ 구조화 데이터(FAQPage JSON-LD)는 글마다 본문 카드 끝에 넣는다 — 코드 삽입 칸이 사이트(Next.js)에 나오는지 확인 전이라서. FAQ 답은 접지 않는다(`faq-i`, AEO). 발행 후 페이지에 FAQPage가 **정확히 1개**인지 확인한다 (D50)
- 에이전트 권한은 초안 작성부터 (common.md 7장)

### 미리보기 확인 (사람)
- 제목·첫 문단 / CTA 링크 작동 / 이미지 / 휴대폰 화면 / SOURCES 링크

### 발행 시간
- 속보: 확인 즉시. 발행 직전에 마감(카드 `deadline` — 원래 공표일 + 72시간, 업무 시간 밖이면 다음 업무일 12:00, D88)을 다시 본다 — 지났으면 속보로 발행하지 않고 깊이 있는 글(교훈 글)로 돌려 설계부터 다시 한다 (D34)
- 일반 글: **평일 오전 8시(JST) 예약**
- 일반 글 예약 시각은 일본 공휴일을 건너뛴다 (D50)
- 하루 게시 상한을 둔다 (오작동 대비) — **6편** (D31 하루 6편). 넘으면 멈추고 사람에게

### 발행 후
- 기존 관련 글 2개 이상에 새 글 링크 추가 — 설계안 `outlines/<slug>.md` 「역링크」 표대로 (D45)
  - 넣기 직전에 `check_outline.py outlines/<slug>.md --verify-links`로 다시 확인한다 (설계 뒤에 기존 글의 소제목이 바뀌었을 수 있다). 없어진 H2는 그 글의 비슷한 위치를 사람에게 묻는다
  - Ghost 연동 전(임시 방식)에는 「기존 글 URL / H2 / 넣을 문장·앵커」를 파일로 만들어 사람이 붙인다
- 공개 글 점검: 제목·SOURCES·남은 초안 표시·FAQPage 1개·og:image (`after_publish.py`). 오류면 아무것도 옮기지 않고 Ghost에서 고친다
- Search Console에 색인 요청 (연결 뒤 — 지금은 남은 일)
- 시트에 발행 기록
- 주제 카드에 `published_at`·`url`을 적고 `status: 발행 완료` → `briefs/done/YYYY-MM/`로 옮긴다. 같은 slug의 research·outlines·drafts·factcheck도 각 폴더의 `done/YYYY-MM/`로 (D40, D44)
