# blog-factcheck (사실 대조)

> v1.5 2026-11-28 · 운영하며 보강 · 공통 규칙: [common.md](common.md)

## 목적
초안의 사실을 하나씩 원문과 대조해 틀린 내용과 근거 없는 내용을 없앤다. **글을 다시 쓰는 단계가 아니다** — 키워드·문장 다듬기·검색 점검은 blog-draft 점검과 blog-polish가 맡는다 (D48)

## 입력
- `drafts/<slug>.md`, 조사 노트 `research/<slug>.md`, 설계안 「쓰지 않을 것」

## 출력
- 수정된 초안 + SOURCES(URL별 번호) → blog-polish로
- `factcheck/<slug>.md` 대조 보고서 (한국어) — 대조표가 다듬기 뒤 재대조의 기준이 된다
- 카드 `status: 다듬기 대기`

## 사람 확인 지점
- 없음 (통과 기준을 못 넘으면 멈추고 사람에게 알린다)

## 규칙

### 다른 눈 (D48)
- 초안을 쓴 세션과 **다른 세션**(또는 초안을 쓰지 않은 서브 에이전트)에서 한다. 쓴 사람이 다시 보면 자기 실수를 놓친다 (D47 보강: 스스로 대조에서 메타의 범위 넓힘을 놓침)
- 같은 세션에서 불렸으면 멈추지 않고 서브 에이전트에게 맡긴다 — 사람이 새 세션을 열 때까지 서 있지 않게 (D79)
- 사람 실습 자리 표시(`:::trial`) 상자는 대조 대상이 아니다. 실습 결과로 섹션을 채운 뒤 `--recheck`로 새 문장을 대조한다 (D79)

### 대조 대상과 방법
- **대조하는 문장 = 사실 문장만** (D103): **숫자·날짜·이름(제품·기능·메뉴·기관)·범위·조건·누가 말했나**가 든 문장(`[S번호]`가 붙은 문장·표 행) + 제목 + 메타 설명. 설명·이음·독자에게 하는 말은 대조하지 않는다 — 실제로 잡은 오류는 모두 숫자·이름·범위·조건이었고, 문장마다 대조하면 초안이 사실 하나씩 끊긴 번역문이 된다 (2026-11-28 사용자: 「정보를 가져와서 왜 다시 대조하지?」)
- 대조 대상: 수치·날짜·고유명사·인용 + **범위·조건·주어·시제** (「予告では」를 빼서 확정처럼, 「可能性」을 단정으로 등)
- 방법: 조사 노트 그 S행의 **원어 원문 문장**과 대조 (노트의 일본어 요약 칸이 아니라). **원문 페이지는 다시 열지 않는다** — 노트에 원문 문장이 있다 (D103, D48 ③·D77을 바꿈)
- 사실이 없는 「설명」 행은 근거를 한 단어로 (의견·안내 문장·질문 등) — 이유를 길게 쓰지 않는다 (D77)
- 표시 없는 문장에 숫자·「」 이름이 있으면 읽는다: 사실이면 출처를 붙이거나 뺀다. 권하는 말이 출처의 권고 범위를 넓히지 않았는지만 본다 (예: 「フルアクセスを許す前に」 → 「使う前に」)
- 판정: **일치 / 불일치 / 확인 불가** → 불일치는 원문대로 고친다(「고침」), 확인 불가는 뺀다(「뺌」)
- `[?]` 출처 없는 사실 문장: 출처 추가 / 의견 표현(「編集部では」)으로 변경 / 삭제 중 하나
- **실명 기업 문장**: 공식 발표의 표현 범위를 넘지 않는지 확인 (명예훼손 방지)
- 설계안 「쓰지 않을 것」이 본문에 없는지 확인

### 출처 다시 열기 (D103 — D48·D61을 바꿈)
- **노트 확인일이 7일보다 오래된 출처만** 다시 연다 (그사이 바뀌었을 수 있다). 핵심 문장이라는 이유로는 열지 않는다
- **속보**: 대조 때는 열지 않는다. 발행 직전에 blog-publish가 1차 출처가 바뀌었는지 **한 번** 본다
- 결과: 그대로 / 바뀜(영향 없음) / 바뀜(영향 있음) / 열리지 않음. **영향 있음·열리지 않음이면 멈춘다** → blog-research로 (노트를 고치는 것은 조사 단계. 새 사실은 노트에 S행이 생긴 뒤에만 본문에)
- 원문 사본은 지금처럼 스크래치패드에만 둔다. 근거는 노트의 원문 문장 + URL 재확인

### 고치는 범위 (D48)
- **틀린 사실이 있는 문장만** 고친다. 다른 문장은 손대지 않는다 (문장 다듬기는 blog-polish)
- 제목·메타를 고치면 설계안도 같이 고친다 (초안 점검이 설계안과 비교한다)
- 고친 뒤 초안 점검(`check_draft.py`)을 다시 통과해야 한다 — 고치다가 키워드·H2·분량을 망가뜨리지 않았는지
- 빼서 **분량이 하한 밑**이 되거나 **차별 포인트가 0**이 되면 늘려 쓰지 않고 **멈춘다** → 사람에게 알리고 blog-research로 되돌린다 (D47과 같은 원칙)

### 통과 기준
- 불일치 0개 (모두 고침)
- 출처 없는 사실 0개 (`[?]` 0)
- 확인 불가인 내용은 글에서 뺀다
- 다시 열어야 하는 출처(확인일 7일 지남)를 모두 열었고, 영향 있는 변경이 없다
- 초안 점검 통과

### SOURCES 형식 (D48)
- **같은 URL은 한 줄**로 묶고 본문에 처음 나온 순서로 1, 2, 3… 번호. blog-publish가 이 번호로 각주 [1][2]를 단다
- 한 줄: 번호 / 제목 / 발행처 / 발표일 / URL / 확인일 / (그 출처의 S번호) — 제목은 원문 페이지 제목(원어). 확인일은 다시 열었으면 그날

### 다듬기 뒤 재대조 (D48)
- blog-polish는 다듬은 뒤 이 스킬의 재대조(`--recheck`)를 부른다. 대조표의 통과 문장과 비교해 **바뀐 사실 문장만** 다시 대조하고 보고서 「재대조 기록」에 적는다
- 어미·순서만 바뀐 문장도 다시 읽는다 — 시제·조건이 바뀌었을 수 있다

### 다듬기 뒤 재대조 (D61)
- `--recheck`가 달라진 단위마다 원래 대조 행과 **사실 표지**(숫자·날짜·판 번호, S번호, 영문·가타카나 고유명사, 한정·범위어 だけ·のみ·すべて·一部·自分で·必ず·以上·以前·まで 등, 부정, 말한 쪽의 태도 求め·呼びかけ·必要 등, 주어)를 비교한다
  - 같으면 「표현만 바뀜」 — 재대조 생략, `--write-skips`로 재대조 기록에 원래 판정·근거를 승계해 적는다
  - 다르거나 새 문장이면 「재대조 대상」 — **다듬기 세션이 노트 원어 원문 문장과 맞춘다** (D103 — 서브 에이전트에게 맡기지 않는다. 다듬기는 사실을 바꾸지 않으므로, 표지가 바뀐 문장만 노트와 맞추면 된다). 뜻이 바뀌었으면 다듬기를 되돌린다
- 재대조는 다듬기(3장)와 일본어 편집자 검토(3-8)를 모두 반영한 **뒤 한 번만**. 재대조가 「고침」을 내면 그 문장만 고치고 그 문장만 다시 확인한다 (전체 재실행 금지)
