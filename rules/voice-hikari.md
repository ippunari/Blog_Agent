| ⚠ 고칠 점 | 「私たちが使ってきた感覚」「私たちの経験では」 (실습 기록 없이) | **금지** — 실습 기록(`[EXP]`)이 있을 때만 (철칙 1, D38) |

## 2. 글의 틀 (초안에서 쓰는 부품)
초안은 Markdown + 아래 상자 표기로 쓴다. Ghost 카드로 바꾸는 것은 blog-publish

### 글 뼈대 — 모든 글 종류 공통 순서 (D47)
```
# 제목
리드 (첫 문단)
:::box 3行まとめ            … 번호 목록 3줄 (모든 글)
:::box こんな方に           … 대상 독자 2~3줄 (일반 글만)
:::box この記事でわかること   … 2~3줄 (모든 글)
:::guide ヒカリちゃんの案内    … 「こんにちは、ヒカリです。」 + 문장
## 본문 H2 … (섹션마다: <!-- 라벨 --> → ## H2 → 굵은 직답 → 본문 → :::matome ヒカリちゃんのまとめ)
:::rep 代表ヤンのひとこと     … 대표 한마디가 있을 때만 (속보·사용법은 끝부분, 그 밖은 결론 근처)
## FAQ
:::cta <CTA 종류>           … 설계안 CTA 표 그대로 (일반 글은 본문 중간 1곳 + 글 끝)
## SOURCES
```
- 그 밖의 상자: `:::note 確認できていないこと` (노트 「아직 확인하지 못한 사항」 중 독자 판단에 필요한 것만, 섹션 안)
- 상자는 `:::` 한 줄로 닫는다

- 글 전체 분량은 설계안 `length` (rules/blog-outline.md 「분량 정하기」), 초안은 상한 이하·90%를 넘으면 경고 (rules/blog-draft.md, D58). 부품 분량은 짧은 속보(상한 3,000자 이하)만 속보 칸, 그 밖은 일반 칸 (D59)

### 2-1. 「ヒカリちゃんの案内」
- 첫 줄은 언제나 「こんにちは、ヒカリです。」
- 다음 2~4문장: 이 글이 무엇인지 → 무엇이 필요한지(사용법) 또는 무엇부터 보면 되는지 → 약속(예: 「例はすべて架空です」 — 사실일 때만)
- 속보는 2문장까지 (부품 분량 표)

예문
> こんにちは、ヒカリです。
> 11月19日に、PHPの修正版が公開されました。うちのサイトが対象かどうかを先に見分けて、それから今日やることを順番にご案内します。

### 2-2. H2 바로 뒤 — 직답
- 굵게 1문장, 전각 40~80자. 설계안 「직답 메모」를 다듬어 쓴다 (사실을 더하지 않는다)
- 정의 H2는 「〇〇とは、〜です。」

예문
> **PHP 8.2のセキュリティサポートは、2026年12月31日に終わります。** [S21]

### 2-3. 본문
- 결론 → 이유 → 예·비유 → 할 일 순
- 한 문단 3~4문장. 표·번호 목록은 설계안 「형식」대로
- 비유는 생활 장면으로 섹션당 1개까지. 피해 기업·사람을 비유로 깎아내리지 않는다
- 숫자·날짜·고유명사·인용은 문장 끝에 출처 표시 `[S4]` (blog-draft 규칙)
- **문단은 떼어 내도 이해되게** 쓴다 — AI 검색은 문단 단위로 인용한다 (common.md 6장 AIO). 문단을 「この」「その」「上の」「次の表」「これは」로 시작하지 않고 주어를 다시 쓴다 (예: 「この修正版は」 → 「11月19日の修正版は」)
- **경고 문장은 같은 문단에 대책과 함께** 쓴다. 공격·악용·漏えい·被害를 말하는 문단에는 독자가 할 일(確かめる・更新する・相談する 등)을 한 문장 붙인다. 경고만 있는 문단을 만들지 않는다 (common.md 4장 「겁주지 않는다」)
- 독자는 IT 담당자가 없는 회사다. 전문 용어는 rules/glossary.md 「용어 수준」대로

### 2-4. 「ヒカリちゃんのまとめ」
- 섹션 끝, 1~2문장. 그 섹션의 할 일·핵심만 (새 사실을 넣지 않는다 — 넣으면 출처 표시)
- 「〜ね」「〜ですよ」 끝맺음은 쓰지 않는다 (7-6). 부드러움은 쉬운 말과 「〜しましょう」「〜がおすすめです」로

예문
> 番号ひとつで「大丈夫」と決めず、まずサーバーを誰が見ているかを確かめましょう。

## 3. 사실 · 의견 · 추측 나누기
| 종류 | 쓰는 말 | 조건 |
|---|---|---|
| 사실 | 「IPAによると」「PHPの公式は〜と案内しています」「公式発表では」 | 노트 S행 `[S번호]` |
| 다른 사람의 검증 | 「〇〇の検証では」 | 노트 S행 (C등급이면 「〜と報告しています」) |
| 편집부 실습 | 「編集部で試しました」「試したところ」 | 노트 실습 기록 `[EXP]`만 |
| 의견 | 「編集部では〜と考えます」「〜をおすすめします」 | 근거 S행이 있는 의견만 |
| 추측 | 「これは推測です」 | 노트에 근거가 있을 때만. 되도록 쓰지 않는다 (철칙 4) |
| 대표 | 「代表ヤンのひとこと」 상자 | 대표 한마디가 있을 때만 `[OP]` |

## 4. 독자 부르기
- 「御社」는 보안·개발 글에서 행동을 권할 때만 (글당 3회 안쪽). 「あなた」는 쓰지 않는다
- 회사 일반은 「自社」「会社」, 독자 전체는 「中小企業の方」

## 5. 쓰지 않는 말 (common.md 4장 금지 표현에 더해)
- 실습 기록 없이: 「私たちの経験では」「使ってきた感覚」「試してみました」「実際に使ってみると」
- 대표 한마디 없이: 「代表は」「ヤンは」 + 의견
- 반말·유행어, 「〜なのだ」, 이모지, 「！」 연속
- 「〜ね」「〜ですよ」「〜よね」 끝맺음 (질문 문장·FAQ 질문만 예외, 7-6)
- 위협: 「今すぐ」「手遅れ」「大変なことに」 (기한을 말할 때는 날짜 숫자로)

## 6. 예문 모음 (글 종류별 도입 첫 문단)
- AI 속보: 「2026年11月〇日、OpenAIは〜を発表しました。[S1] 日本の中小企業にとっては、〜が変わります。[S3]」
- AI 사용법: 「〇〇は無料で使え、最初の1通は10分ほどで準備できます。[EXP]」 (실습 기록이 있을 때)
- 보안 사고 해설: 「〇〇社は11月〇日、不正アクセスがあったと公表しました。[S1] 自社も当てはまるかは、次の2点で見分けられます。」
- 보안 대책 가이드: 「PHP 8.2のサポートは12月31日で終わります。[S21] それまでにやることは三つです。」

## 7. やわらかく読める日本語 (D49)
공식 블로그의 품위는 지키면서 읽기 쉽게. 부드러움은 **말끝(〜ね·〜よ)이 아니라 글자 모양·쉬운 말·리듬**으로 낸다. 8번 blog-polish가 textlint·점검 스크립트로 검사한다

### 7-1. 글자 모양 — 「ひらく」
- 한자 비율 목표 **25~35%**, 보안 글(보안 사고 해설·보안 대책 가이드)은 **25~38%** — 脆弱性·修正版 같은 용어집 말이 많아서. 40% 넘으면 어느 글이든 고친다
- 「」『』 안의 원문 인용·메뉴 이름·공식 표기는 ひらく 대상이 아니다 (원문 그대로)
- 한자 6자 이상 연속 금지 (「情報漏えい対策実施状況」 → 나눠 쓴다)
- 히라가나로 쓰는 말 (文化庁「公用文作成の考え方」 기준)
  - 형식명사: 事→こと, 時→とき, 物→もの, 所→ところ, 為→ため, 訳→わけ
  - 보조동사: 〜て下さい→ください, 〜て頂く→いただく, 〜て見る→みる, 〜て置く→おく, 〜て行く→いく
  - 부사·접속사 등: 既に→すでに, 殆ど→ほとんど, 及び→および, 又は→または, 但し→ただし, 様々→さまざま, 出来る→できる, 有る→ある
- 가타카나 업계어는 쉬운 일본어로: ソリューション→解決策, エビデンス→根拠, リテラシー→知識, スキーム→仕組み (용어집에 있는 말은 용어집대로)

### 7-2. 쉬운 말로 — 한자어·관청 말투 줄이기
| 딱딱함 | 부드럽게 |
|---|---|
| 〜することが可能です / 〜することができます | 〜できます |
| 〜を行う (更新を行う) | 〜する (更新する) |
| 〜において / 〜に関して | 〜で / 〜について |
| 実施する / 把握する / 留意する | 行う / 確かめる / 気をつける |
| 〜とされています (주어 없음) | 〇〇によると〜です (출처를 주어로) |
| 〜ではないでしょうか 반복 | 단정할 수 있으면 단정, 아니면 「〜かもしれません」 1회 |
- 이중 부정 금지 (「〜しないわけではありません」)
- 수동태보다 능동태 (「パスワードの変更が推奨されます」 → 「パスワードを変えましょう」)

#### 7-2-2. 번역투 쓰지 않기 (D56)
원문이 영어·한국어·중국어라도 **일본어로 처음부터 다시 쓴다**. 원문 문장 구조를 옮기지 않는다
| 번역투 | 자연스러운 일본어 |
|---|---|
| 〜と説明されました / 〜と指摘されています (누가 했는지 숨김) | 〇〇は、〜と説明していました (말한 쪽을 주어로) |
| 〜が条件だ / 〜が必要とされる (require 직역) | 〜のときだけ影響します / 〜でなければ影響しません |
| もっとも深刻な「Critical」の脆弱性は (꾸밈말이 겹침) | 「Critical」（もっとも深刻な段階）の脆弱性は / 두 문장으로 |
| 〜することにより / 〜によって〜される | 〜すると / 〜で |
| 一般的でない構成 (uncommon setups 직역) | あまり使われない構成 / 珍しい構成 |
- 사실 대조에서 고친 문장도 같다 — 원문 직역으로 바꿔 넣지 않고 이 규칙대로 쓴 뒤, 다듬기 점검을 다시 통과시킨다

#### 7-2-3. 요즘 일본인이 쓰는 말로 (D57)
| 딱딱함·옛말 | 요즘 말 |
|---|---|
| 既定の設定 / 既定では | 初期設定 / 初期設定のままでは (사이트 용어집도 「初期設定」) |
| 〜のときだけ影響する (조건) | 〜場合に限って影響します / 影響するのは〜場合です |
| AはBは〜 (「は」 두 번) | Aは、Bについて〜 / Bが〜 / 두 문장으로 |
| 〜とは違う設定 | 〜から変えている場合 |
| 構成 (IT 문서 말) | 使い方・環境 (뜻이 같을 때) |
- 기계 점검은 자주 나오는 꼴만 잡는다. 나머지는 다듬기의 **일본어 편집자 검토**(서브 에이전트, blog-polish 3-8)가 본다

- **예외 — 검색어** (D53): 설계안의 메인·서브 키워드에 든 말(バージョン·アップデート·確認方法 등)은 쉬운 말로 바꾸지 않는다. 「バージョン」→「版の番号」처럼 바꾸면 독자가 검색하는 말이 글에서 사라진다

### 7-3. 리듬
- 60자 안팎 안에서 길이를 섞는다 — **문단마다 짧은 문장(30자 이하) 1개 이상**
- 읽점 「、」은 한 문장 3개까지
- 「の」 3연속 금지 (「会社のサイトのサーバーの」), 같은 조사 한 문장 2회 연속 금지
- 본문 체언 끝맺음(体言止め) 금지 — 표·목록·상자 제목은 괜찮다
- 문장 끝을 섞는다: です / ます / ません / でしょう / ましょう (같은 어미 3연속 금지는 blog-polish)

- **문장 사이 연결**: 앞 문장과 화제가 갑자기 바뀌면 순서를 바꾸거나 잇는 말(ところが・そのため・つまり・〜のままでも)을 넣는다. 특히 리드는 사실 → 훅 → 반전 → 할 일이 한 줄기로 (D53)

### 7-4. 명령조 줄이기
- 「〜てください」 한 문단 2회까지. 나머지는 「〜しましょう」「〜がおすすめです」「〜と安心です」로
- 독자를 탓하지 않는다: 「〜していない会社が多いです」 → 「〜は後回しになりがちです」

### 7-4-2. 해야 할 일은 흐리지 않는다 (D52)
- 독자가 **꼭 해야 하는 일**(공식 발표·공공기관이 하라고 한 대책 — 보안 업데이트, 제공처 안내 확인 등)은 「〜する必要があります」로 분명히 쓴다
  - ✕ 「修正版へ更新するのが基本です」「対応の基本は、〜することです」「〜するとよいでしょう」「〜が望ましいです」
  - ○ 「修正版へ更新する必要があります」
- **하면 좋은 일**(선택)은 「〜がおすすめです」「〜しましょう」 — 「必要」와 섞지 않는다
- 강도는 출처에 맞춘다: 출처에 근거가 없는 행동을 「必要があります」로 쓰지 않는다 (철칙 4). 「必要」로 바꾼 문장은 사실 문장이므로 재대조한다
- 「基本」은 「기초 지식」 뜻(「基本の確認方法」)일 때만 쓴다
- H2 직답도 같다: ✕ 「対応方法は、〜するのが基本です」 → ○ 「〜に対応するには、〜する必要があります」 / 출처를 주어로 「〇〇は、〜するよう求めています」도 좋다 (D54)

### 7-5. 일본어 AI 문투 (common.md 4장 금지 표현에 더해)
- 리드를 「〜について解説します」「〜をご紹介します」로 시작하지 않는다
- 쓰지 않는다: 「〜と言っても過言ではありません」「〜が不可欠です」「〜が求められます」「多岐にわたる」「徹底解説」
- 「ぜひ」 글당 1회까지, 「〜することで」 문단당 1회까지
- 「まずは〜から始めてみましょう」 같은 상투 결말을 쓰지 않는다

### 7-6. 「〜ね」「〜ですよ」는 쓰지 않는다
- 회사 공식 블로그이므로 본문·案内·まとめ 상자 모두 「〜ね」「〜ですよ」「〜よね」 끝맺음을 쓰지 않는다 → 「〜ください」「〜しましょう」「〜です」
- 예외: **독자에게 묻는 문장·FAQ 질문**의 부드러운 물음 (「〜で迷っていませんか？」「〜はどうすればいい？」)

### 7-7. 경어
- 「〜させていただきます」 → 「〜します」
- 이중 경어 금지 (「おっしゃられる」「拝見させていただく」)
- 존경·겸양은 1단계까지 — 과하면 거리감이 생긴다
