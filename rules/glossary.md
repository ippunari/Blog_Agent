## 2. 처음 나올 때
- 용어집에 괄호 풀이가 있는 말(예: 「ハルシネーション（AIがもっともらしい誤りを作り出す現象）」)은 **글에서 처음 나올 때 그 풀이를 괄호로** 붙인다. 두 번째부터는 용어만
- **예외 — 영문 이름의 읽는 법** (D100): 용어집 풀이가 가타카나 읽는 법뿐인 영문 회사·제품 이름(「ChatGPT（チャットジーピーティー）」「Google（グーグル）」「Anthropic（アンソロピック）」 등)은 붙이지 않아도 된다. **널리 아는 이름(ChatGPT·Google·Microsoft·Apple·Gemini·Copilot)에는 붙이지 않는다** — 일본 독자에게 오히려 어색하다. 덜 알려진 이름은 처음 한 번 붙여도 된다. 약어 풀이(API·CPI)는 읽는 법이 아니라 설명이므로 그대로
- 용어집에 풀이 괄호가 없는 말은, 독자가 모를 것 같을 때만 직접 짧은 괄호 풀이 (전각 20자 안쪽)
- 영어 약어는 풀어 쓴다: 「情報処理推進機構（IPA）」 「サポート終了（EOL）」 — 용어집 표기가 있으면 그것대로
- 용어집에 없는 전문 용어는 초안 보고의 「용어집 추가 후보」에 적는다 (용어·쉬운 말·나온 글). 사이트 용어집에 넣는 일은 사람 (blog-publish 미리보기 때 같이 본다)

## 2-1. 용어 수준 (D47)
- 독자는 IT 담당자가 없는 중소기업의 사장·실무자다. 용어집에 없는 전문어(영문·가타카나)는 아래 순서로 처리한다
  1. **뺄 수 있으면 뺀다** — 그 말이 없어도 독자가 할 일이 바뀌지 않으면
  2. **행동으로 바꾼다** — 독자가 직접 확인할 수 없는 기술 조건은 「サーバー会社（制作会社）に『〇〇か』と聞いてください」처럼 누구에게 무엇을 물을지로 쓴다
  3. 꼭 써야 하면 처음 나올 때 괄호 풀이 (전각 20자 안쪽)
- 상한: 용어집에 없는 전문어 **짧은 속보(설계·초안 분량 3,000자 이하, D69) 3개 / 그 밖 6개**까지 (고유명사·제품명·검색 키워드·심각도 이름(Critical 등)·시간대(UTC) 제외, 운영하며 보강, D59). 점검 스크립트가 세지 않는 것: 대문자로 시작하는 영문 이름(OpenRouter·Docker)·코드 이름(`…`, `mb_ereg()`, `session.cookie_httponly`)·바로 뒤나 안에 괄호 풀이가 붙은 말(「非推奨（deprecated）」)·나라 이름(アメリカ)·URL (D78). 넘으면 점검 스크립트가 경고한다
- **노트 사실에 나온 말은 그 글의 정해진 이름이다** (D98): 조사 노트 S행(사실·원문 문장)에 나온 기능·메뉴·폴더·역할 이름(ホームフォルダ·テンプレート·オーナー·リリースノート 등)은 상한에 세지 않는다. 바꿔 말하지 말고 그대로 쓰고, 모를 것 같으면 무엇을 하는지 문장으로 먼저 쓴다 (voice-hikari.md 7-5-2). 상한은 노트에도 용어집에도 없이 **글쓴이가 들여온 전문어**를 줄이기 위한 것이다 — 상한을 피하려고 정해진 이름을 풀어 쓰거나 괄호를 끼워 넣지 않는다 (2026-11-28 Claude 글: 「APIキー」 → 「つなぐための鍵」, 「ホームフォルダ（自分用のフォルダ）」)
- 남긴 전문어는 초안 메모 「용어집 추가 후보」에 적는다 (사이트 용어집에 넣으면 다음 글부터 설명이 뜬다)

## 3. 독자에게 익숙한 말 (우리 표기)
| 쓰는 말 | 피하는 말 | 메모 |
|---|---|---|
| ホームページ / サイト | ウェブサイト, Webサイト | 첫 소개는 「ホームページ」, 그다음은 「サイト」도 좋다 |
| 生成AI | ジェネレーティブAI | |
| 脆弱性 (비유로 「穴」) | セキュリティホール | 용어집에 있어 사이트가 설명을 띄운다. 「穴」은 비유로만, 같은 문단에서 두 말을 섞지 않는다 |
| 修正版 / 更新 | パッチ (검색 키워드일 때만 허용), アップデート (키워드일 때만) | 키워드 배치는 설계안 그대로. 키워드이면 H2만이 아니라 본문에도 쓴다 (D53) |
| サポート終了 | EOL 단독 | |
| サーバー会社 / レンタルサーバー | ホスティング事業者 | 용어집 「レンタルサーバー会社」 |
| 管理画面 | ダッシュボード, コンソール | |
| 情報漏えい (본문) | 情報漏洩 (본문) | 記者ハンドブック. **제목·키워드는 검색어대로 「漏洩」 허용** |
| 不正アクセス | ハッキング | 「ハッキング」은 원문 고유명사·인용일 때만 |
| 設定 | コンフィグ | |
| 個人情報 | PII | |
| PHP Free | ― | ⚠ 「PHPフリー」와 통일 여부는 사람이 정한다 (BlogAgent.md 남은 일). 그때까지 사이트 서비스 표기 「PHP Free」 |

- 회사·제품·서비스 이름은 공식 표기 그대로 (AIO). 처음 나올 때 영문 회사는 「米OpenAI」처럼 나라를 붙일 수 있다

## 4. 표기 (記者ハンドブック 기준, 자주 나오는 것)
- 숫자 반각, 날짜 「2026年11月19日」, 시각 「23時」(UTC는 괄호: 「日本時間23時（UTC14時）」)
- 버전: 「PHP 8.2」 (반각 공백), 「8.2系」
- 「〜など」 「〜ごろ」, 「出来る → できる」, 「下さい → ください」, 「時 → とき」(시간이 아닐 때), 「事 → こと」, 「様々 → さまざま」(남발 금지)
- 괄호는 전각 「（）」, 인용은 「」, 책·서비스 이름 안 인용은 『』
