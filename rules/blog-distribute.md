# blog-distribute (SNS 배포)

> v1.3 2026-11-21 · 운영하며 보강 · 공통 규칙: [common.md](common.md)

## 목적
발행한 글을 5개 플랫폼에 맞게 다시 써서 블로그로 사람을 데려온다.

## 언제 (D66)
- **발행 직후 바로**: blog-publish 「발행했어」 점검(after_publish.py)이 통과하면 이어서 만든다. 예약 글은 공개가 확인된 직후(`--verify-live`). 시간을 두지 않는다
- 예약 게시는 쓰지 않는다 — 사람이 확인하고 「올려」 하면 그때 올린다

## 입력
- 발행 완료 카드(`briefs/done/YYYY-MM/`)의 최종 글(`drafts/done/`), 설계안의 SNS 포인트(수치·의견·질문), 대표 이미지
- **SNS 문안의 사실은 최종 글에 있는 것만** (철칙 4)

## 출력
- `publish/done/YYYY-MM/<slug>/sns.md` — 플랫폼별 게시글 5개 (UTM 링크 포함, **원본**), 게시 기록 `sns_posted.json`, 카드 `sns:`·`sns_posted_at`·`sns_platforms`
- `sns/YYYY-MM-DD.md` — **날짜별 모음** (그날 발행한 글의 문안을 발행 순으로, 플랫폼마다 ✅ 올림 / ⏳ 「올려」 대기 / ✋ 붙여 넣기). 보기용이라 스크립트가 점검·게시 때마다 다시 만든다. 사람은 이 파일 하나로 ✋만 손으로 올린다

## 사람 확인 지점
- ◆ 문안을 확인한 뒤 「올려」 → 에이전트가 API로 게시 (철칙 2 — 「올려」 없이는 보내지 않는다)
  - 「올려」만: 방금 보여 준 글 / 「올려 <slug>」: 그 글 (slug 자리에 파일 이름·글 주소도 됨) / 「올려 오늘」·「올려 YYYY-MM-DD」: 그날 아직 안 올린 글 전부 — 먼저 「N편 × 플랫폼」 목록을 보여 주고 사람이 한 번 더 「응」 한 뒤 보낸다
- 사람이 직접: note 붙여 넣기, Facebook 개인 계정 공유, 키가 없는 플랫폼

## 규칙

### 공통
- 플랫폼마다 새로 쓴다 (복사 금지)
- SNS 포인트(수치·의견·질문)를 쓴다
- UTM: `?utm_source={x|threads|note|linkedin|facebook}&utm_medium=social&utm_campaign={slug}`
- 게시 시간: 블로그가 공개된 직후 (일반 글은 오전 8시 공개 직후, 속보는 발행 직후, D66)
- 처음부터 5곳 모두 운영

### 계정
- 기본: 회사 계정
- LinkedIn: 회사 페이지 + 편집부 담당자 개인 계정 (대표 개인 계정은 선택 — 나중에 추가)
- Facebook: 회사 페이지 + 편집부 담당자 개인 계정에서 공유 (대표 개인 계정은 선택)
- 개인 계정 게시도 사람이 확인하고 올린다 (철칙 2). 파일에 개인 이름·계정 ID를 적지 않는다

### 플랫폼별
| 플랫폼 | 길이 | 규칙 |
|---|---|---|
| X | 전각 140자 이내 | 핵심 수치나 질문으로 시작 / **링크는 답글에** / 해시태그 1~2 / 대표 이미지 첨부 |
| Threads | 500자 이내 | ヒカリちゃん 목소리의 대화체 / 링크 1개 |
| note | 1,000~2,000자 | 요약판 + 「全文はブログで」 링크 / **전문 전재 금지** / 해시태그 3~5 |
| LinkedIn | 300~600자 | 회사 관점(글의 핵심 판단·수치), 대표 한마디가 있으면 앞에 / 링크는 첫 댓글 |
| Facebook | 200~400자 | 링크 미리보기 / 중소기업 사장층 대상 |

### 게시 방식 (D66)
| 플랫폼 | 방식 |
|---|---|
| X | API v2 (OAuth 1.0a) — 본문 + 대표 이미지, 링크는 답글. 유료(글 1편 약 $0.22: 본문 $0.015 + 링크 글 $0.20, 2026-11) |
| Threads | Threads API (Meta) — 텍스트 + 링크 1개 |
| LinkedIn | Posts API — 본문, 링크는 첫 댓글. 처음은 편집부 담당자 개인 계정, 회사 페이지는 LinkedIn 심사(Community Management API) 뒤 |
| Facebook | Graph API 회사 페이지 — 본문 + 링크 미리보기. 개인 계정은 API로 게시할 수 없어 사람이 공유 |
| note | 공식 API 없음 → 사람이 붙여 넣는다 (비공식 방법은 쓰지 않는다 — 약관 위험) |

### 점검 (check_sns.py, 오류 0이어야 게시)
- 길이(X는 X 가중치) / 링크 자리·UTM / 해시태그 수 / note 「全文はブログで」 / 복사 금지(본문·플랫폼끼리 30자 이상 같은 구간) / 숫자(단위 포함)가 최종 글에 있는지 / 금지 표현·「〜ね/〜よ」 / 대표 한마디 없이 ヤン / 계정 ID / 공개 URL 200

### 보안
- 모든 계정 2단계 인증 (common.md 7장)
- 키는 로컬 `.env`(권한 600)에 사람이 직접. 계정을 바꿀 때는 `.env` 값만 바꾼다(`SNS_ACCOUNT_LABEL=test|company`)
- 스크립트가 보낼 수 있는 요청은 글·답글·첫 댓글·이미지 올리기와 방금 올린 글 주소 읽기뿐. 삭제·수정·예약·DM·팔로우는 없다
- 같은 글·플랫폼은 한 번만, 플랫폼당 하루 10건, 긴급 정지 `SNS_STOP` 파일
- ⚠ 대표 + 기술 보안팀 승인 전 — 시험 계정(`test`)으로 먼저 운영
