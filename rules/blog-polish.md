# blog-polish (다듬기)

> v1.7 2026-11-28 · 운영하며 보강 · 공통 규칙: [common.md](common.md) (특히 4장 문체, 6장 SEO·AEO·AIO)

## 목적
문장과 톤을 다듬고, SEO·AEO·AIO 규칙을 점검하고, 메타 정보를 쓴다.

## 입력
- 사실 대조를 통과한 초안

## 출력
- 완성 원고 + 메타 정보 + 체크리스트 결과 → blog-publish로
- 놓는 곳: 모두 `drafts/<slug>.md` 하나에 — 본문은 다듬은 원고, 메타는 머리(`seo_title`·`meta`·`og_title`·`og_description`·`excerpt`·`slug`), 체크리스트·바꾼 것·남은 경고는 끝의 「## 다듬기 메모」(한국어). 재대조 결과는 `factcheck/<slug>.md` 「재대조 기록」

## 사람 확인 지점
- 없음 (blog-publish 미리보기에서 확인)

## 규칙

### 우선순위 (D100)
- **자연스러운 일본어가 먼저** — 점검 경고를 없애려고 문장을 어색하게 만들지 않는다. 고치지 않은 경고는 「자연스러워서 둠」으로 남길 수 있다 (voice-hikari.md 7-0)
- 예외 4가지는 자연스러움보다 앞선다: 사실 · 검색어 · 80자 넘는 문장(오류) · 「〜ね」「〜ですよ」 금지

### 순서
다듬기 전 사본 → 문장 다듬기 → 바뀐 사실 문장 재대조(blog-factcheck `--recheck`·`--meaning-diff` — 사실 표지(숫자·이름·조건·부정·주어)가 바뀐 문장만, **이 세션이 노트 원어 원문 문장과** 맞춘다. 서브 에이전트·원문 페이지 다시 열기 없음, D103) → 체크리스트 → 메타
- 편집자 검토 지적은 **원인 문장을 고쳐서** 해결한다 — 해명 문장을 덧붙이지 않는다. 「설명 부족」은 노트(없으면 보충)에서 근거를 찾아 넣는다 (D103)

### 문장 다듬기
- 금지 표현 검사 (common.md 4장)
- 80자 넘는 문장은 반드시 나눈다(오류). 71~80자는 나눌 수 있으면 나눈다(경고, D78 — 61자부터는 매번 8개쯤 남아 무시됐다) — 기준은 「60자 안팎」 (common.md 4장, voice-hikari.md 1장)
- 같은 어미 3번 연속 금지 (〜です。〜です。〜です。)
- 용어 표기 통일 / 전문 용어 첫 등장 풀이 확인
- 필자 목소리 확인 (ヒカリちゃん) / 「써 봤어요」 표현이 실습 기록과 맞는지 / 사람 실습 자리 표시(`:::trial`)는 다듬지 않는다 (D79)
- **やわらかく読める日本語** (voice-hikari.md 7장, D49): ひらく(한자 비율 25~35%, 한자 6자 연속 금지)·쉬운 말·리듬(긴 문장만 이어지면 나누기 — 채우기 짧은 문장은 만들지 않음, 읽점 3개까지, 「の」 3연속·体言止め 금지)·「〜てください」 문단당 2회·AI 문투·「〜ね」「〜ですよ」 끝맺음(질문·FAQ 제외)·경어 과잉
- 자동 교정 도구 실행 → 오류 0
  - textlint: `preset-japanese` + 히라가나 규칙(형식명사·보조동사·부사) + 한자 연속 6자 + 중복 표현 + `prh` 사전(voice-hikari.md 7-2·7-5·7-6·7-7을 사전 파일로)
  - `@textlint-ja/preset-ai-writing`(AI 문투: 굵은 글씨+콜론 목록·과장·강조·「〜します:」 콜론·간결성) — **경고만**(사실·출처 문장도 걸리므로 판단해서 고친다). 「する必要があります → してください」 제안은 7-4-2(D52)와 부딪쳐 넘긴다 (D99)
  - **yomiyasu**(nanaism/yomiyasu, MIT, v3.4.1 고정 — `.claude/skills/blog-polish/vendor/yomiyasu/`) lint: 직역어·비유 동사·決まり文句·같은 「ます」 리듬 — **경고만**, 본문 사본만 넘김, 용어집 말은 허용 목록. 우리 글 틀과 부딪치는 규칙(목록 비율·굵은 글씨 빈도·「**제목**：」 목록)은 뺀다. 「주제 뒤 읽점」·「AではなくB」 같은 참고는 개수만 (D101)
  - 같은 말 몰림(「確かめ」 등 글당 4번)·「アプリの版」·한 문단에 같은 긴 이름 3번 — 경고 (D100)
  - 「初めの状態」「初めは無効」 등 기본값을 흩어 쓴 꼴(→ 「初期設定」)·번역투 3꼴(「〜だけに有効で」「上限に数えられます」「アイコンを持ち」) — 경고 (D102)
  - `preset-ja-technical-writing`은 쓰지 않는다 — である체 기술 문서용이라 「？」·약한 표현 금지가 질문형 H2·「〜かもしれません」과 부딪친다
  - 점검 스크립트: 한자 비율·긴 문장만 이어지는 문단·흐린 말 횟수(D78)·「てください」·体言止め·「ぜひ」 횟수 → 다듬기 보고서에 표로
  - prh 사전은 운영하며 늘린다 (사람이 「이 말 딱딱해」하면 한 줄 추가)
- 보이지 않는 특수 문자 제거
- **제목·H2·메타에 내건 숫자는 본문에서 그 수만큼 보인다** (D102) — 「3段階」「3つの確認点」이라 했으면 본문에 셋 모두 이름·내용이 있어야 한다. 노트에 없어 못 채우면 다듬기에서 사실을 더하지 않고, 숫자를 본문 범위로 줄이거나(제목·H2는 설계안과 같이) 사람에게 묻는다

- **뜻이 바뀔 위험** (D101): 다듬기 시작 때 초안 사본을 두고(`drafts/.before-polish/`, 로컬만), 재대조 전에 yomiyasu diff로 비교 — 숫자·부정·의무·문장 종류가 바뀐 문장은 `[S번호]`가 없어도 재대조 대상에 더한다. 주어가 바뀐 것은 못 잡으므로 재대조를 대신하지 않는다
- 일본어 편집자 검토(서브 에이전트, D57)는 **문단별로 이어 읽고**, 걸리는 문장은 **영어로 되돌려 보아** 영어 구조가 그대로 맞으면 번역투로 본다 (D99)

### 체크리스트
- common.md 6장(SEO 12항목·AEO·AIO)을 항목별 통과 / 미통과 표로

### 메타 정보
- 검색용 제목 (본문 제목과 달라도 됨)
- 메타 설명 (전각 80~120자, 핵심은 앞 50자)
- SNS 공유용 제목·설명
- 목록용 요약 (excerpt) — 메타 설명 문장이나 글 소개 문장으로. 리드·3行まとめ 등 글 머리 문장은 쓰지 않는다 (D54): 사이트가 글 머리(제목 아래)에 excerpt를 보여 줘서 본문 리드와 같은 문장이 두 번 나온다 (D52)
- slug
